# A1. Files and Merge Key

The participant-level analysis dataset was assembled from the NHANES August 2021–August 2023 files `DEMO_L`, `SLQ_L`, and `DSQTOT_L`. The common participant identifier is `SEQN`.

Each of these three files contains one record per participant and has no repeated `SEQN` values. The files were linked sequentially using `SEQN`. Starting with `DEMO_L`, 11,933 participants were present. Of these, 8,501 had a matching record in `SLQ_L`. Linking those participants to `DSQTOT_L` retained 6,615 participants with records in all three files.

| Merge stage | Participants before merge | Participants matched and retained | Participants without a matching record |
|---|---:|---:|---:|
| `DEMO_L` starting file | 11,933 | 11,933 | — |
| Add `SLQ_L` using `SEQN` | 11,933 | 8,501 | 3,432 |
| Add `DSQTOT_L` using `SEQN` | 8,501 | 6,615 | 1,886 |

The resulting three-file dataset contains 6,615 unique participants. Applying the adult age criterion of 20 years or older using `RIDAGEYR` in `DEMO_L` retains 6,064 participants in this merged dataset. The final number for each analysis may be lower when a participant is missing a value for a required exposure or sleep outcome.

`DSQIDS_L` contains individual supplement and antacid reports. It has 11,375 rows for 4,017 distinct participants, and some participants have multiple product records. In the downloaded file, one participant has as many as 30 records. Therefore, raw `DSQIDS_L` rows should not be directly joined to the participant-level analysis table, because that could count some participants multiple times. The product records can be summarized into participant-level exposure variables before being joined using `SEQN`.

The product-reference files are not participant-level files. `DSQIDS_L` links to product information in `DSPI` through `DSDPID`. Ingredient records in `DSII` are also associated with products through `DSDPID`; blend information can be linked from `DSII` to `DSBI` through `DSDIID`. These reference-file links can produce multiple rows per product or ingredient, so they must be handled separately from the one-row-per-participant merge.

Participant counts above were calculated from the downloaded XPT files. The counts describe records available in those files; a missing match in one component file does not, by itself, establish why that participant has no record there.
