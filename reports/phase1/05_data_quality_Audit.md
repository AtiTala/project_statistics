## 5. Data Quality Audit

An initial data-quality audit was conducted on the downloaded NHANES files, focusing on participant and reference identifiers, repeated records, missing values, documented special codes, plausible ranges, and key file links. The original XPT files were retained unchanged. Any recoding or exclusions for analysis will be documented in a separate analysis dataset.

| Check | Findings in the downloaded files | Decision for analysis |
|---|---|---|

| Participant identifiers | `SEQN` is present and unique in `DEMO_L` (11,933 records), `SLQ_L` (8,501 records), and `DSQTOT_L` (8,860 records). No missing `SEQN` values were found in these files. | Use `SEQN` to link participant-level files and verify that each participant has no more than one row after person-level merging. |
| Repeated supplement records | `DSQIDS_L` contains 11,375 product records from 4,017 participants. A participant can report multiple products: 2,506 participants have more than one record, and the maximum is 30 records for one participant. One participant-product pair uses the same unknown-product identifier in two records with different reported intake details. | Multiple product records per person are expected and must not be treated as repeated sleep measurements. The single repeated unknown-product identifier will be flagged and not automatically deleted. |
| Product and ingredient reference links | `DSPI` contains 20,235 unique `DSDPID` product identifiers. All 188,552 `DSII` ingredient records link to a product in `DSPI`; all 37,061 `DSBI` blend-component records link to an ingredient identifier in `DSII`. | Keep reference records separate from participant counts. Check identifier matches after each link so ingredient rows do not multiply participant rows in the analysis dataset. |
| Product-identification status | In `DSQIDS_L`, 11,210 of 11,375 report records have product matches with codes 1–5, which range from exact or near-exact to default matches. The remaining 165 records have code 6 (“no match,” 158 records) or code 9 (“don’t know,” 7 records); these involve 147 distinct product identifiers. | Do not assign an ingredient to an unmatched or unknown product. Retain the reported use information where relevant, but classify the product or ingredient exposure as unresolved for ingredient-specific analyses. |
| Sleep values and missingness | `SLD012` has 113 missing values and `SLD013` has 114 missing values among 8,501 records. NHANES codes a value of 2 as “less than 3 hours” and 14 as “14 hours or more”; these are grouped endpoints, not exact durations. | Keep missing values distinct from reported sleep durations. Do not interpret endpoint codes 2 and 14 as exact hours without an explicitly documented method. |
| Supplement-use status and survey weight | In `DSQTOT_L`, `DSD010` uses 1 = yes, 2 = no, 7 = refused, and 9 = don’t know. There are also missing values. `WTDRD1 = 0` indicates that the Day 1 dietary recall was not done or was incomplete; it is not an ordinary positive survey weight. | Do not recode refused, don’t-know, or missing status as “no.” Apply the documented weight rules when defining the analytic sample and estimating population quantities. |
| Supplement detail special codes | In `DSQIDS_L`, `DSD103` has 6 missing values and 28 “don’t know” codes (`9999`). `DSD122Q` has 5 missing values and 2 “don’t know” codes (`999999`). The observed ordinary values fall within the ranges documented by NHANES. | Treat special codes as non-substantive responses, not as actual days or quantities. Preserve the raw values and recode only in the analysis copy. |
| Age and category codes | `RIDAGEYR` has no missing values in `DEMO_L`, ranges from 0 to 80, and NHANES top-codes ages 80 and older as 80. `RIAGENDR` contains the documented categories 1 and 2, with no missing values in this file. | Treat age 80 as “80 years or older,” not necessarily exactly 80. Treat `RIAGENDR` as a categorical variable, not a numeric measurement. |

Overall, the identifier and reference-file checks were consistent with the documented file structure. Repeated participant records in `DSQIDS_L` and repeated product or ingredient identifiers in the reference files are expected because these files contain product-level and ingredient-level records. They are not, by themselves, evidence of data-entry errors. The main risks for analysis are mishandling special codes, treating missing or unresolved information as a negative response, and allowing multi-row product or ingredient links to create duplicate participant rows.

Before producing final results, the analysis code will report how each special code and missing value is handled, verify the participant count and uniqueness after every merge, and document the number of participants excluded at each eligibility step.
